Mod 扩展机制

模块功能与开发指南

无需修改主项目核心代码，通过挂载 /app/mod 目录即可为 CarNote 动态扩展自定义 API、数据库表、鉴权中间件与自动化任务。

1. 模块功能概览

CarNote 内置了轻量级的外部模块（Mod）加载器。服务在完成数据库初始化后、挂载全局 404 处理前，会自动扫描外部模块目录并按顺序初始化已安装模块。

即插即用热挂载

Docker 容器内默认挂载 /app/mod，放入模块后重启容器即可生效，镜像升级不丢失扩展。

自定义 API 与中间件

直接向 Express 实例注册 /api/mod/* 路由或前置中间件，无缝复用登录态与 API Key 鉴权。

双数据库统一接口

通过注入的 context.db 自动兼容 SQLite 与 PostgreSQL，无需重复编写两套查询代码。

异常隔离保护

单个模块初始化失败会被捕获并输出日志，不会影响主项目或其他正常模块启动。

2. 目录结构规范

容器内默认模块根目录为 /app/mod（可通过环境变量 MOD_PATH 自定义），支持以下两种目录组织方式：

方式一：多模块目录（推荐）

将每个扩展模块独立放在 /app/mod/<模块名>/ 子目录中，系统会自动扫描所有子目录：

/app/mod/ ├── fuel-alert/ │ ├── backend/ │ │ ├── index.js # 【必需】后端入口文件 │ │ ├── routes/ # 可选：子路由 │ │ └── database/ # 可选：建表 SQL │ └── README.md └── webhook-sync/ └── backend/ └── index.js

方式二：单模块直接挂载

若仅需挂载单个模块，也可以直接将模块内容放到 /app/mod/ 根目录下：

/app/mod/ └── backend/ └── index.js # 【必需】后端入口文件

3. 后端入口与 Context 注入

每个模块需在 backend/index.js 中导出 init(app, express, context) 函数（支持 async）：

async function init(app, express, context) { // 1. 从 context 获取主项目数据库与鉴权能力 const { db, auth, uploadDir, modPath } = context; // 2. 初始化表结构、注册中间件或路由 } module.exports = { name: 'my-plugin', // 可选：模块名称 version: '1.0.0', // 可选：版本号 init // 必需：初始化函数 };

Context 上下文对象说明

属性 说明 常用方法 / 导出
context.db 统一数据库接口（兼容 SQLite / PostgreSQL） query(sql, params), get(sql, params), transaction(cb), getDb()
context.auth 用户会话与 API Key 鉴权中间件 authenticateUser, authenticateApiKey, optionalApiKey, isAdmin, checkVehicleOwnership
context.uploadDir 上传文件根目录绝对路径 字符串路径
context.modPath 当前生效的外部模块根目录 默认 /app/mod
context.appRoot 主项目根目录绝对路径 默认 /app
提示：主项目已自动将 /app/backend/node_modules 注入模块解析路径，因此模块可直接 require('express') 等主项目已有依赖；如需额外 npm 包，可在模块目录内自行安装。

4. 完整开发示例（油耗预警模块）

以下示例演示如何在 /app/mod/fuel-alert/backend/index.js 中自动建表并提供带登录校验的读写接口：

async function init(app, express, context) { const { db, auth } = context; const { query, get, getDb } = db; const { authenticateUser, isAdmin } = auth; const DB_TYPE = process.env.DB_TYPE || 'sqlite'; // 1. 初始化专属数据表（兼容 SQLite 与 PostgreSQL） const createTableSql = DB_TYPE === 'postgresql' ? `CREATE TABLE IF NOT EXISTS mod_fuel_alerts ( id SERIAL PRIMARY KEY, user_id INTEGER NOT NULL, threshold REAL NOT NULL DEFAULT 10.0, created_at TIMESTAMP DEFAULT NOW() )` : `CREATE TABLE IF NOT EXISTS mod_fuel_alerts ( id INTEGER PRIMARY KEY AUTOINCREMENT, user_id INTEGER NOT NULL, threshold REAL NOT NULL DEFAULT 10.0, created_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP )`; if (DB_TYPE === 'postgresql') { await getDb().query(createTableSql); } else { await new Promise((resolve, reject) => { getDb().exec(createTableSql, (err) => (err ? reject(err) : resolve())); }); } // 2. 注册模块路由 const router = express.Router(); router.get('/threshold', authenticateUser, async (req, res, next) => { try { const row = await get( 'SELECT threshold FROM mod_fuel_alerts WHERE user_id = ?', [req.userId] ); res.json({ success: true, data: { threshold: row ? row.threshold : 10.0 } }); } catch (err) { next(err); } }); router.post('/threshold', authenticateUser, async (req, res, next) => { try { const threshold = Number(req.body.threshold); if (!Number.isFinite(threshold) || threshold <= 0) { return res.status(400).json({ success: false, message: '阈值必须大于 0' }); } const existing = await get('SELECT id FROM mod_fuel_alerts WHERE user_id = ?', [req.userId]); if (existing) { await query('UPDATE mod_fuel_alerts SET threshold = ? WHERE user_id = ?', [threshold, req.userId]); } else { await query('INSERT INTO mod_fuel_alerts (user_id, threshold) VALUES (?, ?)', [req.userId, threshold]); } res.json({ success: true, message: '保存成功' }); } catch (err) { next(err); } }); router.get('/admin/stats', authenticateUser, isAdmin, async (req, res, next) => { try { const rows = await query('SELECT COUNT(*) AS total FROM mod_fuel_alerts'); res.json({ success: true, data: { total: rows[0]?.total || 0 } }); } catch (err) { next(err); } }); app.use('/api/mod/fuel-alert', router); } module.exports = { name: 'fuel-alert', version: '1.0.0', init };

5. Docker 挂载与启用

在 docker-compose.yml 中已预设 /app/mod 卷映射：

volumes: - ${carnote_data}:/app/data - ${carnote_uploads}:/app/uploads - ${carnote_mod:-carnote_mod}:/app/mod

在 .env 中指定宿主机模块目录并重启服务：

# .env carnote_mod=/volume1/docker/carnote/mod # 重启容器并查看加载日志 docker-compose restart app docker-compose logs -f app

成功加载时可在日志中看到：

[MOD] 正在加载模块 (fuel-alert): /app/mod/fuel-alert/backend/index.js [MOD] 模块加载成功: fuel-alert

6. 双库兼容与排查建议

  • 占位符统一使用 ?：query() 会在 PostgreSQL 模式下自动将 ? 转换为 $1, $2。
  • 表名加模块前缀：建议使用 mod_<模块名>_<表名>，防止与核心表冲突。
  • 布尔字段比较：PostgreSQL 请使用 TRUE / FALSE，JS 参数直接传 Boolean 值。
  • 路由命名空间：建议统一挂载在 /api/mod/<模块名> 下，避免与主项目 API 及前端 SPA 路由冲突。
  • 目录权限：容器内以 node（UID 1000）运行，启动脚本会自动修正 /app/mod 权限，确保宿主机文件可读即可。
